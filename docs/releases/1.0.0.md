# LeapScore 1.0.0 — release notes

Published 2026-11-06 from tag `v1.0.0` (commit `4975b15`). The release workflow ran every
gate, published the tested tarball with provenance, attached the same bytes plus
`SHA256SUMS`, smoked the registry install offline, and moved `v1`.

## Install

Node.js 20 or newer is the only prerequisite; `git` is used for history-derived
indicators when the target is a checkout.

```bash
npx leapscore-scan . --out leapscore-report
```

The package is unscoped: the package name and the command name are both
`leapscore-scan`, so `npx` needs no `-p` flag. The published tarball contains the
launcher, the readable bundle, the README, the Apache-2.0 license, and the manifest —
no scanner sources, no sibling workspace packages, no build step, no runtime
dependencies.

## Action

```yaml
- uses: actions/checkout@v5
  with:
    fetch-depth: 0
- uses: open-legacyleap/leapscore@v1
  with:
    path: .
    fail_under_band: moderate
```

`v1` is the moving major tag; `v1.0.0` is immutable. See the root README for pinning
guidance and the `fetch-depth: 0` rationale.

## Breaking changes

- **Package rename.** The workspace package is now `leapscore-scan` (previously
  `@leapscore/scanner`). Scripts that pass `--workspace @leapscore/scanner` must use the
  new name. The published artifact is the unscoped package; no scope ownership is
  required.
- **Action path inside this repository.** The Action metadata moved from
  `action/action.yml` to the repository root, and `runs.main` is
  `action/dist/index.js`. The dogfood workflow now uses `uses: ./`; the old
  `uses: ./action` form no longer resolves.
- **Sealed engine identity.** The published version is stamped into the bundle, so the
  sealed `engine_version` moves from `0.1.0` to `1.0.0`. Every `score_fingerprint`
  therefore changes, even for an unchanged target. The fingerprint *era* is unchanged
  (`fingerprint_version: 3`), and no public baselines exist from `0.1.0`, so there is no
  comparison to migrate. Deltas computed against a pre-release report will be refused as
  incomparable; re-seal the baseline with `1.0.0` first.

## Publication

Versions are published by the tag-triggered release workflow from the tagged commit,
through npm OIDC trusted publishing with a provenance attestation. No long-lived registry
token is stored in the repository. The same tarball is attached to the GitHub release
with a `SHA256SUMS` file so a registry-less host can install it offline.

## Rollback

A defective version is withdrawn by deprecating it with a message naming its replacement
and moving the major tag back to the last good release. A published version is never
re-published; fixes ship as a new patch.
